# Public validation

`Public app checks` runs on pull requests, main pushes and manual dispatch with read-only permissions, no signing/cloud secrets and GitHub-hosted runners. Linux runs the locked npm install, contract/setup generation and drift checks, TypeScript contract conformance and portable artifact tests. macOS runs the setup recovery, native service-job parser and helper-upgrade fixture suites against isolated synthetic homes, all five Swift test packages, and unsigned generic iOS and Simulator builds. The actual setup installer and optional host launchctl probes are never invoked. Interactive native display remains a manual/headful qualification check. These are build destinations, not newly allocated Simulator devices. Public PRs never use the private self-hosted Mac.

The Apple job uses the hosted `xcode-27` runner and selects `/Applications/Xcode_27.2.app/Contents/Developer`. It verifies Xcode 27.2 build 27B52 before testing. See the [runner software inventory](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md).

Run the same checks from a clean checkout using `npm ci --ignore-scripts`, `npm run check` and `npm test`. For Apple checks, set `RUNNER_TEMP` to a task-owned parent, `CI_SCRATCH_ROOT` to a new run-specific child named `screenpunk-public-*`, and `DEVELOPER_DIR` as above, then run `node tools/ci/storage.mjs init`, `bash tools/ci/apple.sh`, and always `node tools/ci/storage.mjs cleanup`. Locked dependency resolution must succeed; the workflow must not silently update package pins.

Each CI run records ownership, its allocation profile, creation time, retained evidence, resources and disk space. Each disposable GitHub-hosted Apple job starts with at least 28 GiB free. Separate jobs cover setup fixtures, two groups of Swift packages, the device archive and the Simulator build. Each job monitors available disk space during compilation and stops near 8 GiB of total growth or 20 GiB remaining. Local Apple checks retain the 50 GiB startup threshold. The Linux contract job alone uses `storage.mjs init --portable`: at least 1 GiB free and a 512 MiB total budget for its owned scratch, isolated npm cache and checkout-local dependency install. Budget checks run after install and artifact packing. This profile covers lightweight generation, TypeScript checks, fixture tests and portable JSON packing; it does not authorize Swift/Xcode builds, Docker, Simulators or large dependency trees. [GitHub documents 14 GB SSD storage for standard Ubuntu runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners); the first hosted run reported about 13.86 GB free. The bounded portable profile fits those standard runner constraints without deleting runner tools or selecting paid larger runners. It removes only its own `build` directory and retains concise logs plus the updated ownership/cleanup receipt for seven days. The Linux job's isolated npm cache is removed with its owned build directory; its checkout-local dependency install is disposed with the hosted VM. Shared caches and runner-installed tools are not pruned. No full DerivedData, dependency checkout or Simulator tree is uploaded. Copy unique failure evidence elsewhere before retention expires.
