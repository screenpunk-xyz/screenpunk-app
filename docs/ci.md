# Public validation

`Public app checks` runs on pull requests, main pushes and manual dispatch with read-only permissions, no signing/cloud secrets and GitHub-hosted runners. Linux runs the locked npm install, contract/setup generation and drift checks, TypeScript contract conformance and portable artifact tests. macOS runs the setup recovery, native service-job parser and helper-upgrade fixture suites against isolated synthetic homes, all five Swift test packages, and unsigned generic iOS and Simulator builds. The actual setup installer and optional host launchctl probes are never invoked. Interactive native display remains a manual/headful qualification check. These are build destinations, not newly allocated Simulator devices. Public PRs never use the private self-hosted Mac.

The workflow uses standard `macos-26` and explicitly selects `/Applications/Xcode_26.6.app/Contents/Developer`, asserting Xcode 26.6 build 17F113. Official [runner label documentation](https://github.com/actions/runner-images/blob/main/README.md) maps `macos-26` to ARM64; the [macOS 26 ARM image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md) verified October 29, 2026 lists that Xcode (image 20261013.0424.1). Labels receive image updates, so this pins the selected toolchain rather than freezing the entire hosted image. A missing toolchain is a failing check requiring a reviewed pin update.

Run the same checks from a clean checkout using `npm ci --ignore-scripts`, `npm run check` and `npm test`. For Apple checks, set `RUNNER_TEMP` to a task-owned parent, `CI_SCRATCH_ROOT` to a new run-specific child named `screenpunk-public-*`, and `DEVELOPER_DIR` as above, then run `node tools/ci/storage.mjs init`, `bash tools/ci/apple.sh`, and always `node tools/ci/storage.mjs cleanup`. Locked dependency resolution must succeed; the workflow must not silently update package pins.

Each CI run records ownership, its 20 GiB scratch target, creation time, retained evidence, resources and disk space. It fails before installs/builds below 50 GiB free so completed owned outputs can be reviewed first; if a hosted image cannot meet the threshold, treat it as a reported storage block. It removes only its own `build` directory and retains concise logs plus the updated ownership/cleanup receipt for seven days. npm's checkout-local install is disposed with the hosted VM; shared caches are not pruned. No full DerivedData, dependency checkout or Simulator tree is uploaded. Copy unique failure evidence elsewhere before retention expires.

The new repository has been created privately; remaining repository administration and read-back verification must be completed before publication. Require the checks `Contracts and setup (Linux)` and `Unsigned Apple build and regressions`, protect main against force pushes/deletion, require reviews and current checks, and require owner review for workflow, contract, permission and persistence changes. `.github/CODEOWNERS` assigns sensitive paths to `@guysuter`, whose repository admin permission was verified through the GitHub plugin. Require owner reviews in branch protection; the file alone does not activate enforcement. Configure fork workflow approval and restrict Actions to reviewed dependencies. Do not give the public repository access to the private Mac runner group.

Configured files and documentation are not evidence of a successful hosted run or active branch rules. Record first-run URLs and administrator read-back receipts before publication. Official signing and TestFlight orchestration remain in the private repository.
