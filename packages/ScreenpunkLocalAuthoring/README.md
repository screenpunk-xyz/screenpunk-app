# Screenpunk local authoring prototype

Personal local prototype using Codex App Server, an experimental interface unsupported for production or commercial hosted authentication. The tested server is Codex `0.164.0-alpha.11.1`, binary SHA256 `a04752e4d46a4d89e53e6f61c59c5349a638c8ce172ffbf391fd482b4d902a4e`. `ProtocolPin/manifest.json` records the selected generated protocol schema hashes. There is no model or version fallback. GPT-6.1 Sol, high reasoning, and priority service are requested; actual backend served tier is not independently proved.

The adapter uses the SSH child-channel WebSocket supplied by ScreenpunkLocalTransport. Every socket initializes, verifies the server version and dedicated `~/.codex/screenpunk-local` home, requires a ChatGPT account and the requested model/effort, and rejects configured MCP servers. Thread start/resume verifies OpenAI provider, read-only sandbox with no network, user-reviewed approvals, and empty instruction sources. Explicit feature overrides disable supported shell, execution, browser, app, plugin and related facilities. Server approval/input requests are rejected, unexpected tool notifications require attention on the Mac, and no client path approves tools. These checks do not establish an absolute operating-system guarantee that the server can never access Mac files.

Profile threads and immutable request bindings are persisted before turns. Reconciliation searches exact request markers and a matched turn's individually paginated items. A lost start response never triggers automatic resubmission or a different route. Cancellation persists a tombstone before bounded interruption and blocks late results. Complete results pass the shared AuthoringContract before reaching the shared native coordinator; streams never install screens. Native receipts remain idempotent after result-source compaction.

The output schema is a strict wire projection of the shared native Result schema, following the [Structured Outputs requirements](https://developers.openai.com/api/docs/guides/structured-outputs): inline object root, reachable definitions, closed objects, required properties, and nullable wire fields for absent optional Result fields and Mutation.record. Request IDs, digest, base revision and the finite preference revision map are bound to the snapshot. Decoding removes null only from those originally optional fields. Meaningful null values in preferences and revisions survive. The unchanged native validator then enforces canonical shape, byte/UTF-16 bounds, snapshot binding, preference scope and user authorization. The V1 projection passed a bounded synthetic live App Server turn and both native and TypeScript validators. V2 also passed one synthetic live asset-edit turn: the model returned a retain reference and production Swift decoding/materialization plus TypeScript validation preserved the exact original asset bytes. Candidate evidence records the bounded turn and cleanup.

Keychain stores a generated Ed25519 private key and App Server bearer behind a credential reference using device-only accessibility. Only the OpenSSH public key is displayed. Secrets are non-Codable and redacted. Forget deletes only the exact referenced item. Mac sign-in, SSH enablement, authorized keys and a protected bearer file are user setup steps; this package does not copy login credentials or alter Mac SSH configuration.

Test Connection performs a harmless strict JSON roundtrip, disconnects, initializes again, and reads the same saved result. It does not create an authoring delivery record or install a screen. Failures after a known test turn attempt a bounded interrupt before closing.

V2 model prompts reference a versioned, digest-bound static definition context supplied through trusted developer instructions on every new or resumed thread. Only exact canonical design guidance, runtime and service operation definitions are compacted. Current service capability states, permissions, preferences, source references, revision bindings and the original snapshot digest remain in each request. A compact turn requires the matching verified thread on the current socket; missing context retains the full snapshot, and stale connection bindings cannot start a turn. The complete sealed snapshot remains durable for validation and recovery.

`LocalAuthoringTransportV2` implements the parallel `AuthoringTransportV2` API. It shares the durable ledger with v1 records, decoding an absent contract version as v1 and retaining existing results, receipts, pins and thread IDs. V2 records store their exact logical result separately. A v1 adapter cannot submit, cancel or acknowledge a v2 binding. The new profile thread key is `LocalAuthoringTransportV2.threadKey(profileID:)`; v1 history stays untouched. V2 static runtime guidance goes in supported `developerInstructions`, while turns contain only a bounded request snapshot and marker. Native v2 validation remains authoritative for write/retain/delete accounting. `requiredAssets` is the only additional optional screen field adapted from null; write and retain branch fields cannot be silently discarded.

`preflight(timeoutNanoseconds:)` defaults to five seconds and returns `LocalAgentReadiness.ready`, `.unavailable(reason)` or `.repairRequired(reason)`. It sends initialization/account/model/MCP checks and a static-instruction-only versioned thread start/resume to verify returned security settings; it sends no authoring request, source or `turn/start`. Timeout cancellation fences late thread persistence. Host identity, binding, unsupported version, unsafe settings and invalid credential failures require repair. Ordinary not-configured/unreachable/timeout/disconnected/sign-in/model/credential-unavailable states let Automatic consider its matching configured Cloud route. A preflight never authorizes cross-route replay after a request is prepared.

`LocalAuthoringTransport.testConnection(configuration:)` accepts a staged pairing candidate. Its disclosed structured-response/reconnect test does not write the active endpoint, profile threads or successful-connection timestamp. The receipt contains the isolated test thread ID. The pairing coordinator commits the candidate only after this test succeeds.
